# Implementation status

Updated: 2026-10-29

## Present in source

- Rust CLI commands: `scan`, `rules`, opt-in `explain <scan-report.json> <finding-id>`, and `serve` for the local dashboard/API.
- `pr-check` evaluates a schema version 1 report against a configurable severity threshold, emits a Markdown comment in JSON, and fails closed on incomplete scans. It simulates a PR gate locally; it does not post to GitHub.
- `benchmark` runs repeated scans and emits median wall time, files/sec, and non-empty supported source lines/sec for the current machine. It includes process startup and does not claim logical LOC.
- `Dockerfile` and `compose.yaml` start the authenticated local dashboard with a read-only workspace mount, non-root user, dropped Linux capabilities, read-only container filesystem, and loopback-only host port mapping. The server requires a loopback `--public-origin` when bound to the container interface.
- Cargo package declares Rust 1.85 as its minimum supported toolchain for edition 2024.
- Python syntax parsing through Tree-sitter; a leading UTF-8 BOM is replaced with equal-width spaces for parsing so byte offsets remain aligned with the original source.
- Bounded repository walk and report: scans `.py`, `.env`, and `.env.*` with case-insensitive extension/name matching; skips symlinks and common generated directories (case-insensitive names); rechecks symlink status and canonical containment before reading and rejects paths that change during the read. This is a best-effort race check, not an atomic no-follow open guarantee. It caps files at 1 MiB, total directory entries at 25,000, directory depth at 256, and findings at 10,000. If directory collection completes with more than 5,000 supported files, it scans the first 5,000 paths in lexical order and marks the report incomplete; if a traversal limit stops collection early, only paths reached before the limit are considered. It checks a 30-second deadline between directory entries and files, recording incomplete scans when limits are reached. The deadline cannot interrupt a single blocking filesystem operation or parser call. Reads are capped at 1 MiB plus one byte so a file that grows after metadata inspection cannot trigger an unbounded allocation. Directory enumeration and metadata errors are recorded at the affected relative path while scanning continues through accessible siblings until a global limit is reached.
- Text, JSON, and SARIF 2.1.0 output with repository-relative paths, sorted findings and errors, deterministic per-location IDs (including columns for repeated same-line secret assignments), rule versions, evidence roles, and source/sink trace entries where supported. IDs use non-cryptographic 64-bit FNV-1a and have a theoretical collision risk.
- JSON scan reports expose a top-level `complete` flag and structured errors; text and SARIF also mark incomplete scans.
- Text output never describes an incomplete scan with zero findings as a clean scan.
- Text-mode paths escape Unicode control characters and common bidi/zero-width formatting characters to prevent filenames from rewriting or visually reordering terminal output; JSON and SARIF retain the original repository-relative paths.
- Text-mode scan errors and echoed invalid command/argument values use the same terminal escaping for control and bidi/zero-width formatting characters.
- SARIF includes the complete implemented rule catalog even when a scan has no findings.
- Repeated detections for the same rule and source location are collapsed into one finding.
- Local source-to-sink tracking follows simple assignments in function source order, including annotated assignments, assignment expressions, and `for` loop targets; simple `del` statements clear tracked names. It does not model branch paths or aliases.
- Request-source markers include common Flask, Django, and ASGI request attributes for query/form/body data, headers, cookies, files, URL/path values, `request.META`, `request.environ`, and `request.stream`; framework identity and trust semantics are not verified.
- Local dashboard in `web/`: branded report viewer with the supplied SecuTron artwork, JSON import, severity/search filtering, finding evidence/trace/limitations, completeness indicators, rule coverage, and local scan controls. `secutron serve` binds to loopback by default and serves authenticated `/api/scan` and `/api/scan/stream`; the stream authenticates its first bounded JSON message, reports started/running/completed/error events, and includes scan duration and files/sec telemetry. The server requires a one-time random bearer token, exact Host/Origin checks, a single concurrent scan, bounded request bodies, and does not persist reports. An explicit non-loopback bind requires a loopback `--public-origin` pinned to the same port; Compose maps this to host loopback only. The browser holds the token only in page memory. It can download report JSON and copy a CLI explanation command; it does not contact the model provider.
- Initial fixture repository in `fixtures/vulnerable-shop/` contains intentionally vulnerable, secure-negative, `.env` edge, and syntax-error samples. Eight Rust integration tests invoke the CLI and verify rule coverage (including weak and imported crypto/random calls), negative results, redaction, parsing, incomplete-scan exit status, deterministic JSON, SARIF metadata/results, and the authenticated local server.
- Text output shows sanitized evidence roles and rule limitations, without printing source lines or secret values.
- `PY.SECRET.LITERAL`: direct, chained, annotated, or assignment-expression assignment, credential-like string keys in dictionaries, credential-like keyword arguments, and credential-like parameter defaults with direct string literal values. Interpolated f-strings are excluded. Parenthesized literal values and common Python string prefixes are handled; placeholder matching is case-insensitive after literal delimiters are removed. Credential-name matching is case-insensitive after non-alphanumeric characters are removed. The reported range covers only the variable, key, argument, or parameter name.
- `GEN.SECRET.LITERAL`: non-placeholder value assigned to a credential-like key in `.env` files, including assignments prefixed by `export` and whitespace; an initial UTF-8 BOM is ignored for parsing and keys are limited to ASCII letters, digits, `_`, `.`, and `-`. Quoted values honor escaped delimiters and are unwrapped only when followed by whitespace, end-of-value, or a whitespace-separated comment. Unquoted inline comments begin at `#` only when preceded by whitespace. Matching is case-insensitive after non-alphanumeric characters are removed. Values are not emitted and the reported range covers only the key.
- `PY.SQL.UNTRUSTED`: direct request markers or simple locally tracked request-derived variables in positional or recognized `operation=`, `query=`, or `sql=` arguments to calls named `execute` or `executemany`, including bare calls and raw request-supplied queries.
- `PY.COMMAND.UNTRUSTED`: direct source marker or a simple locally tracked request-derived variable in `os.system`/`os.popen` or `asyncio.create_subprocess_shell`, or in the positional or `args=` input to calls named `run`, `popen`, `Popen`, or `call` with a top-level `shell=` value of `True`, a statically nonzero numeric literal, or a nonempty string literal. Parenthesized literals are accepted; library identity for process-like calls is not resolved.
- `PY.PATH.UNTRUSTED`: direct source marker or a simple locally tracked request-derived variable in the positional or `file=` path argument to built-in `open(...)`, or in a method named `open`'s receiver or positional/`path=`/`file=` argument. Method/library identity is not resolved.
- `PY.CODE.UNTRUSTED`: direct request markers or simple locally tracked request-derived variables passed as the first positional argument to calls spelled `eval(...)`, `exec(...)`, `builtins.eval(...)`, `builtins.exec(...)`, `__builtins__.eval(...)`, or `__builtins__.exec(...)`. Other aliases and name shadowing are not resolved.
- `PY.CRYPTO.WEAK`: direct calls spelled `md5`, `sha1`, `hashlib.md5`, `hashlib.sha1`, or common PyCryptodome MD5/SHA-1 constructors. Module identity and purpose are heuristic; legitimate checksums can be flagged.
- `PY.RANDOM.INSECURE`: common direct calls to Python `random` functions, including `getrandbits`; aliases, module identity, and security context are not resolved. Secure `secrets` APIs are not matched.
- Nebius Token Factory explanation request: OpenAI-compatible HTTPS chat completions, configured by `NEBIUS_API_KEY`, `SECUTRON_API_BASE`, and `SECUTRON_MODEL`. The command prompts before sending one selected finding's allowlisted metadata/evidence, enforces payload/response limits, sets a timeout, disables redirects, and prints latency/token usage when returned. It sends no source files or `.env` data. No patch generation, sandbox, or auto-fix loop is implemented; provider behavior has not been integration-tested with credentials.
- Local dashboard API: `secutron serve [--bind 127.0.0.1:8765]` generates a 256-bit random bearer token for the process session, serves `web/`, and exposes authenticated `POST /api/scan`. The scan request accepts a path string and invokes the CLI executable without a shell. It allows one scan at a time, checks the exact Host and browser Origin, limits JSON request size, does not cache reports, and returns the CLI JSON report. Non-loopback binding requires a same-port loopback `--public-origin`; use only with a host port mapped to loopback as in the provided Compose file.

## Material limits

- Direct-expression matching plus a simple source-order local-variable pass within each function. Ordinary string and comment text is excluded from request-source marker matching; executable expressions inside f-string interpolation are retained. Branch paths, loop paths, aliases, arbitrary attribute flows, imports, framework semantics, sanitizers, and interprocedural flow are not modeled. This is not a general taint engine.
- Calls whose method name is `execute` or `executemany` can be treated as SQL sinks; library identity and parameterization semantics are not resolved.
- Calls whose method name is `open` can be treated as filesystem sinks; path containment is not evaluated.
- Calls spelled `eval`, `exec`, `builtins.eval`, `builtins.exec`, `__builtins__.eval`, or `__builtins__.exec` can be treated as code-execution sinks even if the names are shadowed; other aliases are not recognized.
- Direct request access must match one of the built-in, case-sensitive marker spellings in source at identifier boundaries. Framework identity and trust semantics are not verified. Sink method names are also matched case-sensitively. Variable propagation can miss destructuring, parameter passing, aliases, and non-assignment forms; branch ordering can also create false positives.
- Parse errors mark the scan incomplete, but the parser may still produce candidate findings from recovered syntax.
- Confidence values are hand-set rule metadata, not calibrated exploit probabilities or measured accuracy.
- Secret placeholder suppression matches a small exact-value list and whole-value `$NAME`, `${...}`, or `{{...}}` templates; credentials containing placeholder-like words may still be reported.
- Patch generation, an OS-isolated validation sandbox, in-dashboard AI explanation/token telemetry, GitHub comment posting, and dependency scanning are not implemented. The AI explanation is provider-dependent and has not been exercised against a live account.

## Build and verification

On 2026-10-29, the baseline Rust suite passed five provider unit tests and eight scanner/API integration tests. The current suite passes seven unit tests and ten integration tests, including WebSocket authentication and completion telemetry; `node --check web/app.js` and `git diff --check` pass. The two-run vulnerable-fixture benchmark measured one file, 26 non-empty lines, and 37.53 ms median process time (26.65 files/sec, 692.81 non-empty lines/sec) in this environment; these are smoke measurements, not portable performance claims. A local PR-gate smoke test returned `failure` for four high findings. Docker engine, live AI-provider, and sandbox validation remain unverified.
